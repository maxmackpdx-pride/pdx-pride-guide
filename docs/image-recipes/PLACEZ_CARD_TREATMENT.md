# Treat PlaceZ Photos

Create a consistent photo treatment while keeping each real place recognizable. Treat the photo layer as the deliverable unless the user requests a card mockup. Preserve the existing card layout, text, logo treatment, category chip, buttons, border geometry, and aspect ratio during a narrow photo edit. For a requested complete card, use the approved etched-blueprint deep-glass treatment below. Apply only the requested scope; do not redesign or publish the website.

Use **3D wireframing** as the key term for tight blueprint-like spatial linework around the real building edges and through visible sky, approximately 70% primary category accent and 30% complement, with no added neon tubes.

For every complete card or format/spacing revision, read references/current-format-contract.md (source-recipe reference: `references/current-format-contract.md`) and its bundled CSS snapshots. Match Square 250 × 250, Tall 200 × 403, Small 136 × 170, Wide-Map 360 × 216, and responsive Expanded exactly. Use the five completed venue examples as the shared baseline; Pizza Thief/#6 is still in progress. Preserve the approved +4px Square/Tall/Expanded footer clearance and 2px Small heart inset as precisely defined there.

## Establish the inputs

- **Determine the place type and assigned card color first.** Resolve the category token, actual edge color, and complementary accent before selecting colors or generating art. Use that intended card color for primary wirework and paper tears.
- When sourcing new photos, also read **Make PlaceZ Building Images**, especially its **Find and verify the source photos** workflow. Establish the exact venue, address, and period; use user-supplied originals, official sources, and authorized/open-license alternatives; distinguish deliverable source images from view-only corroboration. Inspect fronts, storefront/windows, complementary angles, relevant interior evidence, and the actual road/asphalt. Never mix relocation/renovation states or use a recent repost as proof of a recent capture.
- Collect and inspect multiple distinct authentic target photographs, aiming for 3–5 useful views when available. A crop of one photo is not an independent source. Use them for facade/window evidence; record creator, date, URL, and license, and resolve conflicts between dates. Use the latest approved card references for style only. Never treat an earlier generated reconstruction as evidence of unseen building details.
- Resolve the place identity, source provenance, intended crop, category token, complementary token, and actual card-edge color. Read references/project-sources.md (source-recipe reference: `references/project-sources.md`) when locating project tokens or the four original venue references.
- Prefer current project token values or explicit user input over visual guesses. For a supplied flattened card, the visible border is a usable color reference when source tokens are unavailable. Do not silently substitute a nearby neon hue. If a required photo or color cannot be recovered, ask for that missing input rather than fabricate it.
- For a full card, locate the exact current venue-logo asset already on file in the project and verify it against the live card or its source reference. That project asset takes precedence over another logo from the venue's official site. Do not substitute an official-site variant, retype the name, or invent a mark. If the on-file asset cannot be found, ask for it rather than silently replacing it. Resolve neighborhood/location copy from a reliable source.
- Read references/approved-card-treatment.md (source-recipe reference: `references/approved-card-treatment.md`) and inspect the bundled corrected Darcelle plus all four series cards before a full-card treatment or consistency comparison. Verify files against references/asset-manifest.json (source-recipe reference: `references/asset-manifest.json`). The corrected Darcelle/series proportions supersede the earlier single glass concept; current guide-correct edges supersede bitmap rim weight.
- For a batch, resolve these inputs separately for every place. Creating this reusable skill does not itself authorize generating every location or publishing assets.

## Apply the treatment

### Accurate photographic base

Preserve facade proportions, roofline, window count, pane divisions, frames, doors, signage, and street geometry visible in the real reference. Keep the building crisp and photographic, with detailed HDR tonal range and realistic materials. Do not make it a generic cyberpunk building or replace its windows with invented details. Change perspective, weather, lighting, signage, people, or framing only when requested or already part of the approved target treatment. Mark reconstructions as concepts rather than current documentary photographs.

### Wide building framing

Show most of the real building face-forward, with its full visible roofline and outside edges, visible atmospheric sky behind the wireframes, and enough surrounding space to read the whole facade. No cars or other vehicles. Resolve architecture hidden by vehicles from additional authentic views instead of inventing it. Favor the real source photo's wider field of view; do not progressively zoom in or tighten the crop across revisions. Establish one approved crop and uniform scale, then hold them fixed for later styling passes. If the user asks to pull back, return to the original source for the wider composition instead of generating unseen architecture. Keep the approved centered logo position unless the user requests relocation; widening the photo does not authorize moving it into the sky, above the building, or into a corner. Keep the logo legible without letting it hide most of the building; reduce its scale modestly when necessary for a requested wider building view rather than enlarging the photo to fill space.

### Preserve the treatment through card framing

Keep the approved torn-paper texture and **3D wireframing** visible in the finished card, not merely in the uncropped artwork. Within each format's existing image bounds, retain a readable band of textured tears, layered fibers, and fine spatial meshes in the sky and around the building. Do not let a tight crop, mask, logo, or bottom fade remove most of the collage and wirework. Lower-body glass etching does not substitute for visible sky/building wireframes.

For a framing correction, pull back or reposition the photographic composition uniformly within the fixed art area, using the authentic wider source and approved artwork as the respective architecture and style authorities. Preserve facade geometry, exact centered logo, card dimensions, image-area height, text, controls, and shared spacing. Do not stretch the building, invent missing architecture, enlarge the photo header, or shrink controls to recover decoration. Inspect every requested format at actual display size, including Small and responsive Expanded; an intact large source image alone does not pass. Once corrected and approved, hold that crop for later styling passes.

### Protect source geometry before adding style

Treat the original photograph and exact on-file project logo as protected inputs, not inspiration to reconstruct. Record the intended uniform scale/crop, the logo's original width-to-height ratio, and several visible facade landmarks before generation: roof corners, window groups and pane counts, column/door positions. Keep an unmodified source copy. Never use a generated predecessor as the authority for these details.

In the image-tool prompt, label the original photo as the photographic plate and the logo as an intact transparent decal. Specify uniform scaling only; no redraw, retyping, beveling, inflated outlines, changed rays, altered proportions, or new architectural detail. Apply a logo shadow outside its silhouette instead of changing the mark itself. Keep decoration outside important facade and logo features. On a correction, provide the original sources again and lock all unrelated card regions.

Generative editing can still redraw protected inputs despite those instructions. Do not equate recognizability or correct spelling with preservation. If exact source fidelity is required for implementation, retain the actual original photo and logo as separate image layers, with generated styling confined to separate overlays; do not replace them with a full-card generated reconstruction. Follow the current environment's image-editing requirements and do not expand scope into a website implementation unless requested.

### Exact centered white logo

Use the exact on-file logo as a separate, intact transparent layer centered in the photo area, matching the approved reference placement. Render the mark white, preserving its original silhouette, internal cutouts, letterforms, proportions, and alpha. Apply a separate sharp dark offset shadow outside that silhouette, matching the approved reference; do not add blur, a neon halo, bevels, outlines, colored plaques, or decorative rays absent from the project asset. A wider building crop must leave this centered placement intact unless the user explicitly requests relocation.

Keep the source asset separate from the photo and generated styling. Do not ask a generative model to recreate the logo or treat a generated approximation as the original. Use an authorized compositing workflow that preserves the actual asset; follow the current environment's image-editing requirements. If the available workflow cannot preserve it exactly, disclose that limitation rather than claiming an exact match. Record the source path, uniform display scale, photo-relative center, and shadow offset with the working assets so later revisions preserve the same treatment.

### Outzide-inspired 3D wireframing

Require both visible building-edge tracing and sky wireframes. Trace the actual visible roofline, stepped cornices, outer corners, and outside vertical silhouette with fine lines matching the card-edge color. Follow the architecture rather than outlining only the photo rectangle or card perimeter. Extend connected three-dimensional wireframe grids, angular mesh planes, and perspective construction lines upward and outward into the sky and surrounding negative space. A few scraps at the top border or etching only on the lower card do not satisfy this treatment.

Use dense, fine, tight three-dimensional blueprint/wire motifs with clear perspective. Concentrate them around the outer edges, sky, and space surrounding the building. Keep substantially fewer lines across the facade so the real architecture remains the subject. Use sharp graphic lines, intersections, and restrained printed glow where the reference calls for it. Neon token colors are acceptable; luminous tubes, thick neon ropes, or tube-like outlines are not.

Allocate approximately 70% of the colored wire/accent treatment to the place's category token and 30% to its complementary token. This ratio describes the added accents, not the total pixels or the building's natural colors. Keep the actual card-edge color separate when the card has an override or specialty edge.

### Torn xerox collage

Keep the irregular ripped-paper silhouettes, layered collage, paper fibers, and xerox grain. **Make the white torn paper match the primary category accent.** Recolor the formerly white, off-white, cream, or beige torn-paper edges and fibers to the verified primary category/card accent, not the 30% complementary wire color. Use the exact map-collage texture reference preserved in **Make PlaceZ Building Images**; Tucker reaffirmed this reference and recoloring on November 11, 2026. Preserve darker textured shading rather than flattening the paper into smooth plastic. Do not leave bright white paper rims. Do not recolor white windows, printed signage, logos, or other unrelated white content.

For a gradient or multicolor edge, follow the approved edge treatment across adjacent torn sections rather than inventing a single replacement color; ask only if the supplied edge does not resolve the intended treatment.

### Approved continuous blacktop rainbow

Read the approved rainbow road correction (source-recipe reference: `references/approved-rainbow-road.md`) and inspect its bundled Sports Bra image before applying or revising the road treatment. It supersedes older endpoint rainbows: use one continuous textured red/pink → orange → yellow → green → cyan → blue → violet/purple logo-spectrum overlay, approximately 60% overlay-strength guidance, with real asphalt grain, cracks and shading visible. Do not turn it into separated neon puddles, colored light pools, wet reflections, or the historical repeated cyan/yellow/magenta/orange sequence.

Confine the treatment to existing blacktop/asphalt and follow its ground-plane perspective. Do not spread it onto sidewalks, buildings, windows, sky, or the whole card, or invent/enlarge road for the effect. Omit it if asphalt is absent unless the user explicitly authorized another surface for that image; the earlier Pizza Thief sidewalk exception remains task-specific. Keep this spectrum separate from the 70/30 category/complement wire colors. For a narrow correction, preserve every unrelated approved region and current card geometry.

### Longer fade into black

Extend the photo's lower fade farther upward into the image, with a longer, smooth transition into the black card body. Carry the fade across the full photo width and include the lower collage/wire layers so there is no hard horizontal seam, light paper shelf, gray haze, or isolated bright strip at the join. Finish at the card body's actual black. Preserve important facade and window details above the fade. Do not satisfy this request merely by adding a black block or moving the card's text.

## Etched-blueprint deep-glass card

Match the corrected Darcelle and four-card series as a whole, not isolated effects. Use the current format contract and shared kit for exact geometry. In the historical square treatment reference, the photo-to-body transition is near the middle, leaving the lower half for readable information and actions; this is not a rule to force on every current format. The approved 1254-pixel example places the main central torn transition around y625–656 (about 50–52% of canvas height); this is proportional visual guidance, never fixed device CSS. Fit the wider facade and visible sky inside that photo area rather than growing the header and shrinking the controls. Preserve generous type/button scale and consistent spacing. Use an irregular torn/halftone join, not the rejected heavy taped or framed-photo treatment. Read the linked reference for precedence, visual anchors, and source caveats.

Keep one consistent text hierarchy across venues and card sizes: treated exterior and real logo above; location, bold uppercase venue title, category chip, wide View details action with northeast arrow, and separate outline-heart action below. Use the same type family, role-based weights and relative sizes, alignment, padding, and spacing rules throughout the series. Use the exact current kit rules for each format, including its responsive conditions; do not merely adapt a large square proportionally, invent a different hierarchy per card, or shrink text/buttons to fit a larger photo or logo. Preserve the requested aspect ratio and existing placements except for requested hierarchy corrections.

Include a separate readable venue title by default. Omit it only when the exact logo is simply the venue's name and remains clearly readable at the intended card size. A symbol, monogram, decorative mark, or difficult-to-read lettering does not replace the title. **Darcelle XV needs a readable title.** Keep this title separate from the protected logo; setting the title as text does not authorize retyping or redrawing the logo. If a wordmark qualifies for omission, keep the remaining information and actions in the shared hierarchy rather than redesigning that card. This title rule supersedes inconsistent or missing titles in older card references.

The lower card is near-black, dimensional OLED/deep glass, not gray paper or a flat matte panel. Add restrained directional sheen and hairline blueprint etching mainly down the right edge and along the bottom; leave the text and action area calm and readable. Use the same category/complement pair as the upper photo. Keep texture subdued rather than dusty, cloudy, or noisy. Keep category/complement color in fine, low-opacity etched line geometry and restrained reflections over the near-black substrate, never broad opaque colored panels, filled polygons, or brown-orange patches. Preserve the approved glass depth and visible fine geometry without washing the body in the accent color. A dark tinted block is not a substitute for etched glass.

Keep the exact on-file logo white and centered in the photo area, with the separate sharp dark offset shadow shown in the reference. Do not blur it into a neon halo, stretch it, change its letterforms, or duplicate it as a second invented architectural sign. Real signage already in the photo remains evidence of the building.

Use the guide's standard colored rim: **1 CSS px**, with a **separate 2 CSS px black keyline**. Do not turn the black keyline into additional colored border. Use the current format contract's per-format radius and a muted accent mix from current glass tokens; no thick luminous tube, solid neon perimeter band, or broad glow frame. For specialty edges use the applicable current PlaceZ rule, not the ordinary rim or a guessed width. Read the linked guide before selecting a specialty recipe. Scale CSS measures consistently to the raster preview's intended display width. If a bitmap cannot prove exact CSS compliance, call it a visual preview rather than a verified implementation.

Keep the photographic base, 70/30 accent balance, torn-xerox color rules, asphalt-only rainbow, and long bottom fade above. Etched glass is a lower-card surface treatment, not permission to replace those requirements or cover the building with geometry.

## Execute and verify

Use the image-editing tool available in the current environment and supply the source/reference images explicitly. For a new treatment, use the real photo plus the approved style reference. For a narrow revision, use the latest artwork as the edit target and constrain edits to the requested areas. Avoid baking card controls, labels, and decorative logo overlays into a photo-only asset.

Inspect the output at full image size and in the intended card crop:

- Does the facade still match the real source, especially every visible window and door?
- Does the framing show most of the face-forward building, its roofline and outside edges, and real atmospheric sky, with no cars or vehicles? Has the sky remained visible without becoming an oversized bright header? Compare with authentic sources and the approved crop; reject unintended zoom.
- Are fine card-color lines visibly hugging the building's actual roofline, steps, corners, and outer silhouette, rather than merely its image/card border?
- Do dense perspective wireframes visibly extend into the sky and surrounding space, with the complementary color mixed throughout at roughly 30% of the added accents? Do not pass an output with missing outlines, mostly empty sky, or only perimeter/lower-card decoration.
- Are the wires fine and spatial, with most line density off the facade and no neon tubes?
- Are all torn-paper parts the card-edge color while unrelated whites remain unchanged?
- Does the rainbow match the bundled approved Sports Bra continuous logo spectrum and strength, with textured asphalt still visible, no separated light pools, no invented roadway, and no spill outside the authorized ground surface?
- Does the photo fade smoothly farther into black without a seam or loss of key building details?
- Is the logo the exact on-file project asset, white and centered within the photo area with a sharp dark offset shadow? Compare the original silhouette, internal cutouts, letterforms, and proportions directly with the source; an official-site variant or recognizable generated redraw fails this check. Verify that widening the building view did not move the logo upward into the sky or into a corner.
- For a card revision, are the existing text, layout, exact on-file logo, controls, and border otherwise intact except for requested corrections?
- Do all requested formats match the exact current kit dimensions, padding, gaps, responsive bounds, and approved footer/heart adjustments in references/current-format-contract.md (source-recipe reference: `references/current-format-contract.md`)? Compare against the five completed examples; do not mark #6 as a finished reference.
- Across venues and intended display sizes, do the location, title, category, and actions follow the same typography, alignment, spacing, and relative emphasis? Is a readable venue title present unless the exact logo is simply the clearly readable name? Confirm that Darcelle XV includes its title. Reject per-card hierarchy drift even when each card looks acceptable on its own.
- In every requested card size, are textured torn edges/fibers and sky/building 3D wireframing visibly retained after cropping, masking, logo placement, and fading? Reject an output where those features exist only outside the displayed crop or collapse to a smooth rim. Correct art framing within the fixed layout.
- Does the lower body retain a near-black deep-glass substrate with fine category/complement right/bottom geometry, restrained sheen, and clear text? Reject broad opaque color panels, filled polygons, brown-orange patches, paper, fog, or broad neon glow.
- Is the colored outer edge visually hairline at intended display size, with a distinct black keyline, rather than the thick rim in the older approved visual?
- Compare a new-location result with the five completed examples in the same format at equal display sizes: exact current-kit photo/details balance and geometry, prominent centered white logo, readable large type/actions, torn transition, glass depth, fine dense sky/edge 3D wireframing, palette balance, and hairline rim. Treat the historical roughly half-card photo/details split as square-reference guidance only; do not impose it on Tall, Small, Wide-Map, or Expanded. Reject an unintentionally oversized bright header, faint watermark logo, undersized controls, or heavy taped photo frame. Check architecture and logo fidelity against the original inputs separately. A successful style-family match is not pixel-identical reproducibility or proof of facade accuracy.

Use a separate source-fidelity check in addition to the style check. Compare the output directly with the original photo and logo at matched crop/scale: window groups and pane counts, roof/column alignment, foreground objects, logo aspect ratio, outline/ray shapes, and letterforms. Check only visible details; do not mark covered areas as verified. If measurements are available, report the measured quantity and method rather than a vague accuracy percentage. Do not infer exactness from an image-generation prompt or visual similarity alone.

For a visible fidelity failure, make a targeted preservation pass using the original sources while locking the rest of the card. Recheck against the source, not merely the preceding generation. If the pass still redraws details or improves one feature while worsening another, say so. For a requested consistency test, report style consistency and source fidelity as separate outcomes; do not label a source-drift result a strict preservation pass or publication-ready asset.

Treat the building-edge outline, sky extension, complementary-color mix, and wide framing as explicit pass/fail checks on every treatment, including source-preservation passes. Correct visible failures before delivery where the available tools permit. Retain the original source and credits, and describe any reconstruction honestly. Deliver only the requested assets or previews. Preserve source-license obligations if later publication is authorized; a generated derivative does not erase them.

**With the first delivery of each new building artwork or complete card, include the actual reference images used**, clearly labeled with source/credit/date/license and architecture-versus-style role. Preserve the source files and deliver them alongside the artwork, not only links or a later assurance. Flag uncertain facade/window details. Approval of the finished style does not verify reconstruction or waive source rights.
