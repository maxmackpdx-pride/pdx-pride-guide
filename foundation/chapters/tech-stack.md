# Tech Stack

Zaylist needs a stack that one founder can understand, afford, recover, and explain. The goal is not the largest architecture. The goal is a trustworthy operating map with explicit ownership, evidence, cost, security, and exit paths.

## Product doctrine across stack and systems

The product remains human-first for UI, copy, and member workflows. At the same time, the platform must be highly agent-readable and operator-friendly.

- Public identity, provenance, freshness, relationships, permissions, limitations, and available actions should be exposed through documented, machine-readable interfaces where helpful.
- Identify and support agent visitors as first-class users for usage and completion tracking.
- Keep authentication boundaries for protected content and actions, while leaving useful public information inviting and clear.

## Consistency lock

- Human-first UI and copy remains the default.
- Agent readability is built as a first-class documented capability when it supports people outcomes.
- Any automations or machine interfaces run behind explicit authorization and privacy-safe controls.
- No stack or policy mutation without Tucker approval.

## Governing decision

Maintain one canonical, agent-readable Tech Stack guide in `foundation/tech-stack/`. It records current systems and unknowns without storing credentials. A read-only Tech Stack Monitor gathers evidence and routes relevant findings to Marketing, Business, Design, and Engineering while Tucker retains authority over every mutation.

## System boundary

The Library documents purpose, ownership, evidence, relationships, cost, failure impact, and recovery. Provider dashboards and Railway hold secrets and mutable operational state. The production repository implements application behavior. None becomes a competing Foundation or Design System.

## AI collaborators

Codex and Claude are part of Tucker's working tech stack. Codex owns recurring local agents, implementation, continuity, and bounded operations where configured. Claude is an external AI collaborator for bounded research, review, synthesis, and second opinions. ChatGPT may contribute through Tucker's private project context and specialized finance handoffs.

These tools are working surfaces, not independent authorities. They must cite or preserve source boundaries, label recommendations, and follow the minimum-necessary rule. API keys, passwords, private founder-finance records, NDA-protected material, recipient data, and unrelated personal context must not be sent to an external AI service unless Tucker explicitly authorizes that exact use.
