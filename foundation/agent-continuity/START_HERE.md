# Start here: Zaylist agent memory

Read this before any Zaylist task that depends on earlier conversations.

## Five-minute recovery

1. Read `manifest.json` for authority, privacy, and routing.
2. Read `current-context.json` for the current priority, blockers, and handoffs.
3. Check `conflicts.json`. If a conflict affects your task, stop and ask Tucker instead of choosing a convenient version.
4. Load only the routed Foundation decision, Design System bundle, continuity note, or context packet needed for your assignment.
5. State which facts are accepted, which are verified production evidence, which are recommendations, and which remain unknown.

## Always-on skills baseline

Every replacement model should treat these as baseline:

- `zaylist-foundation`
- `zaylist-design-system`
- `zay-logo-design`
- `zaylist-living-guide-builder`

## Never infer permission

Reading a note does not authorize publishing, deploying, spending, messaging, changing production, or promoting a rule. Permissions come from Tucker's explicit direction and the current task.

## Write back only when material

Create a checkpoint when founder direction, evidence, status, a conflict, blocker, owner, or next action changed. Otherwise leave the memory untouched.

## Finish every material task with

- Outcome
- Evidence
- Decision status
- Remaining unknowns
- Next owner and action
- Approval required
- Sources
- Visibility
- Freshness or expiry
