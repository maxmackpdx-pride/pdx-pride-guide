Floating inbox

The single inbox surface: a bottom sheet on mobile, a bottom-right panel behind a draggable button on desktop. Three tabs, three account views, and one rule that shapes all of it. Everything happens in place. Reading, replying, archiving, approving and resolving never change the URL, so you never lose the page you were on to answer a message.

Frame

2px solid var(--neon-blue) with a layered blue glow, matching the site's glowing cards. Sheet #0d0d10, nav #0a0a0c, rows #131317, hover #1b1b21, hairlines #1c1c22.

Tabs

INBOX, POSTS, STATS. Under INBOX, an account switcher: Personal, Admin (the shared keyholder queue) and Owner (the Owner Desk, primary owner only). Opening with pending items defaults to Admin, or Owner when only desk items wait.

Thread detail

Opening a thread swaps the list for the detail in place: back header, message bubbles, reply composer, archive. The account tabs, the personal toolbar and the bottom search all hide while it is open.

Desktop button

The floating button appears at 641px and up and can be dragged to reposition. It carries the attention count: unread messages plus the admin queue plus the owner desk.

Mobile offset

The sheet sits 96px above the bottom because the nav dock is around 84px tall and env(safe-area-inset-bottom) resolves to 0 in-browser. Any lower and the composer tucks under the dock.

Bar helper

hbars(rows, color, suffix) takes label and value pairs, finds the max, and returns a width per row with a 2% floor so an empty row is still visible.

06 · Rules

In place, always

No router navigation inside the overlay, ever. New actions mutate and stay. The whole point is that answering something never costs you your place.

Badge parity

The pending count must sum every category the admin queue renders. The owner desk is counted separately. A badge that disagrees with the list is a bug, not a rounding choice.

Archive is local

Archiving is client-side in localStorage, so it hides a thread for you without touching anyone else's copy.

Silent empty

Every queue query falls back to an empty list on error, so a failed request reads as "nothing here" rather than an error state. When something is missing, check the endpoint before the UI.

Private stays private

Missed connection and gifting replies never render publicly: the count shows, the bodies do not. Reveal is the poster's choice and theirs alone.

Never

No second inbox. The full /inbox page and the older admin page still exist, but this is the primary surface: keep endpoint parity and do not fork the queue.
