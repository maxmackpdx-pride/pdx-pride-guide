Context primaries

There is no fallback primary. Every screen belongs to a surface family, and that family owns its primary action colour: acid yellow on marketing, events and boards, cyan in the Hub, magenta in admin, violet on the owner desk, and the two beach greens. Each is set by a single attribute, and everything inside reads --accent and --c, so buttons, chips, blooms and glass edges re-key together and no component needs to know where it is.

Rules

One primary per screen

A screen belongs to exactly one context. Do not nest scopes to get two action colours in one view: that is what makes a page read as noise.

Data keeps its own colour

Day colours, board accents, category rings and the status ramp are data. A context never repaints them, so a Wednesday event is still yellow inside the admin queue.

Cyan stays navigation

--link and --focus-ring are cyan everywhere, and so is the default action now. That is deliberate, not a collision: it means one colour carries "this does something" across the product. Links stay underlined so a link never reads as a button.

Green is one green

--green-acid #39FF14 is the only green in the system. The old #00EE44 is retired; --neon-green survives only as a deprecated alias.

Yellow's other jobs

Identity, not action

Acid yellow is also the Gifting board's accent (--board-gifting), and board accents are identity: a context never repaints them.

Flair and state

FREE tags, slogan stickers, live dots and the going pill are yellow too. On yellow surfaces that means the primary button has to earn its weight through the lit plate, not through colour alone.

Never a day

#CCFF00 is not a day colour and never has been. Wednesday is #FFEE00, a different yellow, and the two must not be swapped.
